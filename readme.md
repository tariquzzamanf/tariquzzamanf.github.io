# Academic website

Source for [mdtariquzzaman.github.io](https://mdtariquzzaman.github.io/). The site itself is the source of truth for biography, research, publications, and contact details; this file only documents how the site is built and published.

## About the site

The site has five pages: **Home**, **Research**, **Publications**, **CV**, and **Personal**. Pages are generated with Python’s standard library and served as plain HTML and CSS. Content and navigation work without JavaScript; optional JavaScript provides theme switching, the mobile menu, and section highlighting. No package installation or external font service is required.

## Preview locally

With Python 3 installed, run these commands from the repository root:

```sh
python3 scripts/build.py
python3 -m http.server 8765 --bind 127.0.0.1
```

Open [localhost:8765](http://127.0.0.1:8765). Stop the server with `Ctrl+C`.

### IUT publication CSV

`publication_input_iut_website.csv` is prepared for the publication importer at the [IUT faculty profile](https://cse.iutoic-dhaka.edu/profile/tariquzzaman/publications). Keep the header exactly as `Type,Date,Info`, use an ISO date (`YYYY-MM-DD`), and quote each complete citation in `Info` so commas do not create extra columns.

Write each `Info` value as a readable scholarly citation: preserve the approved author order, put the complete paper title in quotation marks, include the actual venue or repository and year, and finish with the canonical external publication URL. Use the publication host (for example, ACL Anthology or arXiv) as the final link so search engines and visitors reach the paper record directly; do not link to this website or the IUT profile from the citation. ArXiv-only papers are preprints and must use `Others` in `Type`, with wording such as `arXiv preprint, arXiv:<identifier> (<year>)`. Keep a workshop or conference classification when the work has an approved workshop/conference venue even if its accessible paper copy is hosted on arXiv.

When adding or changing a row, validate the file before importing it:

```sh
python3 - <<'PY'
import csv
with open('publication_input_iut_website.csv', newline='') as f:
    rows = list(csv.DictReader(f))
assert all(set(row) == {'Type', 'Date', 'Info'} for row in rows)
assert all(row['Date'].count('-') == 2 for row in rows)
assert all(row['Type'] == 'Others' for row in rows if 'arXiv' in row['Info'])
print(f'{len(rows)} publication rows are valid')
PY
```

See [agents.md](agents.md) for the maintained content and design decisions.

## Google Scholar metrics

`scripts/sync_scholar.py` refreshes the citation, h-index, and i10-index summary in `content/scholar-metrics.json`. It does not import papers; those are curated in `content/publications.json`. Google Scholar blocks requests from cloud servers such as GitHub Actions, so run it by hand from your own connection:

```sh
python3 scripts/sync_scholar.py            # fetch, save, and rebuild the site
python3 scripts/sync_scholar.py --dry-run  # fetch and print only
```

A successful run prints `Scholar metrics updated` (or `unchanged`) with the values, sets the refreshed date to today, and rebuilds the pages. Any failure — a Scholar block, a CAPTCHA page, a missing or malformed metrics row, or a certificate problem — prints `SYNC FAILED` with the reason, changes nothing, and exits with status 1, so there is no need to cross-check the numbers. On a macOS python.org install, a certificate error is fixed once by running `Install Certificates.command` from the Python folder in `/Applications`.

## Deployment

GitHub Pages serves the `main` branch from the repository root (**Settings → Pages → Source: Deploy from a branch**, `main`, `/ (root)`); `.nojekyll` keeps the files served as-is. To publish, rebuild if needed, then commit and push:

```sh
python3 scripts/sync_scholar.py   # optional: refresh metrics and rebuild
git add -A && git commit -m "Update site" && git push
```
